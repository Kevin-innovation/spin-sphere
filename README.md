터미널에 문자만으로 3D 구를 그리고 회전시키는 프로그램입니다. **그래픽 라이브러리를 하나도 쓰지 않습니다.** 화면의 문자 한 칸마다 "여기 구가 보이나? 보인다면 얼마나 밝나?"를 수학으로 직접 계산합니다.

## 1. 실행 방법

### 1-1. 준비물

**Node.js만 있으면 됩니다.** 설치할 패키지가 하나도 없습니다. (`npm install` 안 해도 됩니다. `package.json`도 필요 없습니다.)

먼저 Node.js가 깔려 있는지 확인하세요:

```bash
node --version
```

`v18.0.0` 같은 버전 번호가 나오면 성공입니다. `command not found`가 나오면 [nodejs.org](https://nodejs.org)에서 LTS 버전을 설치하세요. (macOS에서 Homebrew를 쓴다면 `brew install node`)

### 1-2. 내려받고 실행하기

```bash
git clone https://github.com/Kevin-innovation/spin-sphere.git
cd spin-sphere
node sphere.js
```

구가 회전하기 시작합니다. **종료는 `Ctrl + C`** 입니다.

### 1-3. 옵션

| 명령 | 설명 |
|---|---|
| `node sphere.js` | 기본. **검은 배경** 터미널용 |
| `node sphere.js --reverse` | **흰 배경** 터미널용 (밝기 램프를 뒤집음) |

> **어느 걸 써야 하나요?** 실행했는데 구의 밝은 쪽과 어두운 쪽이 뒤바뀐 것처럼 어색하면 `--reverse`를 붙이세요. 터미널 배경색에 따라 문자의 체감 밝기가 정반대가 되기 때문입니다. (검은 배경에서는 `@`가 밝게 보이지만, 흰 배경에서는 `@`가 어둡게 보입니다.)

### 1-4. 정지 화면 한 장만 뽑아보기

애니메이션 없이 한 프레임만 보고 싶다면:

```bash
node -e 'console.log(require("./sphere.js").frame(1200, 72, 26))'
```

- 첫 번째 숫자 `1200` = 시간(밀리초). 바꾸면 광원 각도가 바뀝니다.
- 두 번째 `72` = 가로 칸 수, 세 번째 `26` = 세로 줄 수.

파일로 저장하려면:

```bash
node -e 'console.log(require("./sphere.js").frame(1200, 72, 26))' > sphere.txt
```

### 1-5. 잘 안 될 때

**구가 세로로 길쭉하다**
터미널 폰트의 가로:세로 비율이 1:2가 아닙니다. `sphere.js`의 `CHAR_ASPECT` 값을 `1.8`이나 `2.2`로 조정하세요.

**화면이 심하게 깜빡인다**
터미널이 느린 경우입니다. `FPS`를 `15`로 낮춰보세요.

**구가 잘려 보인다**
터미널 창을 키우세요. 창 크기는 매 프레임 자동으로 다시 읽습니다.

**명암이 반대로 보인다**
`--reverse` 옵션을 붙이세요.

**종료했는데 커서가 안 보인다**
터미널에 아래를 입력하면 돌아옵니다.

```bash
printf '\e[?25h'
```

## 2. 30초 요약: 어떻게 작동하나

터미널 화면을 **가로 80칸 × 세로 24줄 = 1920개의 픽셀**이라고 생각합니다. 각 칸마다 아래 6단계를 거쳐 문자 하나를 고릅니다.

```
   ① 좌표 변환      화면 좌표 (col, row)  →  수학 좌표 (x, y)
                    "왼쪽 위 기준, 칸 단위"  →  "한가운데 기준, -1~+1"
                              ↓
   ② 구가 있나?      z² = 1 − (x² + y²)
                    z² ≤ 0 이면 → 공백 ' ' 찍고 끝
                              ↓
   ③ 법선 구하기     z = √(z²)  →  이 지점의 법선 = (x, y, z)
                    (단위구에서는 위치가 곧 법선! 계산이 필요 없음)
                              ↓
   ④ 밝기 계산       diffuse = 0.5 × max(0, 법선 · 광원방향)
                    (내적 = 두 방향이 얼마나 같은 쪽을 보는가)
                              ↓
   ⑤ 색 만들기       색 = SKY × diffuse + GROUND
                              ↓
   ⑥ 문자 고르기     Y = 0.2126R + 0.7152G + 0.0722B  (휘도)
                    문자 = RAMP[ round(Y × 10) ]
```

이걸 1920번 반복하면 한 장면이 완성됩니다. 그리고 **광원의 각도 θ를 조금 바꿔서** 초당 30번 다시 그리면 → 회전 애니메이션.

> 💡 **놀라운 사실**: 구가 도는 게 아니라 **빛이 돕니다.** 단색 구는 어느 방향으로 돌려도 모양이 같기 때문에, 빛만 돌려도 눈에는 구가 도는 것처럼 보입니다. 계산이 훨씬 쌉니다. 텍스처를 입히려면 그때는 진짜로 구를 돌려야 합니다.
>

## 3. 용어 사전

코드 주석과 아래 설명에 계속 나오는 말들을 먼저 정리합니다.

### 3-1. 스칼라와 벡터 — 가장 중요한 구분

#### 스칼라 (scalar)

**크기만 있고 방향이 없는 값. 그냥 숫자 하나입니다.**

| 예시 | 값 |
|---|---|
| 온도 | 25도 |
| 시간 | 3.5초 |
| 밝기 | 0.7 |
| 몸무게 | 60kg |

"25도"에 "동쪽으로"를 붙이면 이상하죠? 방향이라는 개념 자체가 없습니다. 그래서 스칼라입니다.

어원: scale(눈금, 저울)에서 왔습니다. **눈금 위의 한 점**이라는 뜻입니다.

#### 벡터 (vector)

**크기와 방향을 함께 가진 값. 숫자를 여러 개 묶은 것입니다.**

| 예시 | 값 | 의미 |
|---|---|---|
| 위치 | (3, 4, 5) | 원점에서 x로 3, y로 4, z로 5만큼 |
| 속도 | (10, 0, -2) | 이 방향으로 이 빠르기로 |
| 색 | (0.5, 0.85, 1.5) | 빨강 0.5, 초록 0.85, 파랑 1.5 |
| 빛의 방향 | (1.41, 1, 0.2) | 빛이 오는 쪽 |

> **색이 왜 벡터인가요?** 색은 방향이 없어 보이지만, 수학적으로는 "RGB 3차원 공간의 한 점"입니다. (1,0,0)은 빨강 축 방향, (0,1,0)은 초록 축 방향. 실제로 벡터 연산(더하기, 스칼라 곱)이 그대로 색 연산(빛 합치기, 밝기 조절)이 됩니다. **이게 이 프로젝트의 핵심 아이디어 중 하나입니다.**

#### 스칼라 곱 (scalar multiplication)

**벡터 하나에 숫자 하나를 곱하는 것.** 모든 성분에 똑같이 곱합니다.

```
(0.5, 0.85, 1.5) × 0.4 = (0.20, 0.34, 0.60)
```

성분들의 **비율은 그대로**, **크기만** 변합니다. 색으로 말하면: 색조(무슨 색인지)는 유지, 밝기만 어두워짐.

기하학적으로는 화살표의 **방향은 그대로, 길이만 0.4배**가 됩니다.

#### 벡터 합 (vector addition)

**같은 자리끼리 더합니다.**

```
(0.20, 0.34, 0.60) + (0.2, 0.1, 0.05) = (0.40, 0.44, 0.65)
```

조명에서는 "여러 광원의 빛이 한 표면에 동시에 닿을 때"를 의미합니다. 빛은 서로 간섭 없이 그냥 더해집니다.

#### 내적 (dot product, 점곱)

**벡터 둘을 넣으면 스칼라 하나가 나오는 연산.** 기호는 가운뎃점 `·`.

```
(a₁, a₂, a₃) · (b₁, b₂, b₃) = a₁b₁ + a₂b₂ + a₃b₃
```

같은 자리끼리 곱해서 **전부 더합니다.** 결과는 숫자 하나(스칼라).

한 줄 요약: **두 방향이 얼마나 같은 쪽을 보는지를 재는 자.**

👉 자세한 의미는 [4-4장](#4-4-내적과-램버트-코사인-법칙--이-코드의-심장)에서 다룹니다.

### 3-2. 기하 용어

**법선** — normal, 法線
표면에 **수직인** 방향을 가리키는 벡터. "이 면이 어느 쪽을 보고 있나"를 나타냅니다. 조명 계산의 필수 재료입니다.

**단위벡터** — unit vector
길이가 정확히 1인 벡터. 방향 정보만 담고 크기 정보는 버린 것입니다.

**정규화** — normalize
벡터를 그 길이로 나눠 단위벡터로 만드는 것. `(3,4,0)` → 길이 5 → `(0.6, 0.8, 0)`

**정사영** — orthographic projection
3D를 2D로 납작하게 누르는 방법 중 하나. 원근감이 없어서 멀리 있어도 크기가 그대로입니다. 이 프로그램이 쓰는 방식입니다.

**원근 투영** — perspective projection
멀수록 작게 보이는 방식. 사람 눈·카메라와 같습니다.

### 3-3. 조명 용어

**diffuse** — 난반사, 亂反射
거친 표면에서 빛이 **사방으로 흩어지는** 반사. 어느 각도에서 봐도 밝기가 같습니다. 물체의 기본 명암을 만듭니다. 종이, 벽, 천이 이런 표면입니다.

**specular** — 정반사, 하이라이트
매끄러운 표면에서 빛이 **거울처럼 튕기는** 반사. 보는 각도에 따라 반짝임이 움직입니다. 금속, 물, 눈동자가 이런 표면입니다. **이 코드에는 없습니다.**

**ambient** — 환경광
어디서 오는지 특정할 수 없이 공간에 깔려 있는 은은한 빛. 벽과 바닥에 수없이 반사되어 온 빛의 근사치입니다. 그림자를 완전한 검정으로 만들지 않는 역할을 합니다.

**램버트 반사** — Lambertian
diffuse를 계산하는 가장 기본 모델. `밝기 ∝ cos(입사각)`

---

### 3-4. 색·화면 용어

**휘도** — luminance, 輝度
색을 사람 눈이 느끼는 **밝기 하나**로 압축한 값. 기호는 `Y`입니다.

**양자화** — quantization
연속된 값을 띄엄띄엄한 단계로 바꾸는 것. 아날로그를 디지털로 바꾸는 일입니다.

**계조** — gradation, 階調
밝기의 단계 수. 이 코드에서는 문자 11개 = 11계조입니다.

**RAMP** — ASCII ramp, gray ramp
직역하면 '경사로'. 어두운 문자에서 밝은 문자로 완만하게 올라가는 문자열입니다.

**인덱스 / 인덱싱** — index / indexing
인덱스는 배열의 칸 번호, 인덱싱은 그 번호로 값을 꺼내는 것입니다. `RAMP[5]`

**0 기반 색인** — 0-based index
첫 칸이 0번인 방식. JavaScript, C, Python이 모두 이 방식입니다.

**클램핑** — clamping
값을 정해진 범위 안으로 강제로 자르는 것. `clamp01(1.7) = 1`

**종횡비** — aspect ratio
가로:세로 비율. 터미널 글자는 보통 1:2입니다.

### 3-5. 약자 총정리

**RGB** — Red, Green, Blue
빛의 삼원색. 색을 이 3개 숫자로 표현합니다.

**FPS** — Frames Per Second
초당 화면을 몇 번 다시 그리는가.

**NDC** — Normalized Device Coordinates
정규화 장치 좌표. 화면 크기와 무관하게 −1 ~ +1 범위를 쓰는 좌표계입니다.

**ANSI** — American National Standards Institute
여기서는 터미널을 제어하는 특수 문자열 규격(ANSI escape code)을 가리킵니다.

**HDR** — High Dynamic Range
0~1을 넘는 밝기까지 다루는 방식.

**Rec.709** — ITU-R Recommendation BT.709
HDTV와 sRGB가 쓰는 국제 색 표준. 휘도 가중치의 출처입니다.

**SDF** — Signed Distance Function
부호 있는 거리 함수. 확장 아이디어에서 등장합니다.

**b2ASCII** — brightness to ASCII
밝기를 ASCII 문자로. 원본 코드의 함수명입니다.

**uTime** — uniform + time
셰이더에서 모든 픽셀이 **공유하는** 시간값.

**vPos** — varying + position
셰이더에서 픽셀마다 **달라지는** 위치값.

**LTS** — Long Term Support
장기 지원 버전. Node.js를 설치할 때 고르는 그것입니다.

> **uniform과 varying이 뭔가요?** GPU 셰이더에서 값을 두 종류로 나눠 부르는 말입니다.
>
> - **uniform** — 모든 픽셀이 똑같이 받는 값. 시간, 화면 크기, 광원 위치 등
> - **varying** — 픽셀마다 달라지는 값. 그 픽셀의 좌표 등
>
> 이 코드에서는 `uTime`, `cols`, `rows`가 uniform 역할이고, 루프 안의 `x`, `y`가 varying 역할입니다.

## 4. 수학 원리 상세

### 4-1. 좌표계 변환 — 화면 좌표를 수학 좌표로

**문제:** 터미널과 수학은 좌표를 세는 방식이 완전히 다릅니다.

| | 터미널 좌표 | 수학 좌표 |
|---|---|---|
| 원점 | 왼쪽 **위** 모서리 | **한가운데** |
| x 방향 | 오른쪽으로 증가 | 오른쪽으로 증가 ✅ |
| y 방향 | **아래**로 증가 ⚠️ | **위**로 증가 |
| 단위 | 문자 칸 (정수) | 실수, 구의 반지름이 1 |

세 가지를 동시에 처리해야 합니다.

#### ① 평행이동 — 원점을 가운데로

```js
col - (cols - 1) / 2
```

가로 80칸이면 `(80-1)/2 = 39.5`를 뺍니다.

```
col:      0     1    ...   39   40   ...   78   79
결과:  -39.5 -38.5   ...  -0.5  0.5  ...  38.5  39.5
```

정확히 좌우 대칭이 됩니다. `(cols-1)/2`인 이유는 0번부터 79번까지 **80개의 칸**의 중간이 39.5이기 때문입니다. (`cols/2 = 40`이면 반 칸 어긋납니다.)

#### ② 크기 조정 — 구의 가장자리를 ±1로

```js
/ radius
```

이렇게 하면 화면 크기와 무관하게 구의 지름이 항상 -1 ~ +1이 됩니다. **이런 좌표계를 NDC(정규화 장치 좌표)라고 부릅니다.** 터미널이 80칸이든 200칸이든 수학 공식은 하나로 통일됩니다.

#### ③ 종횡비 보정 — 글자가 정사각형이 아니라서

터미널 글자는 보통 **가로 1 : 세로 2**입니다. 보정하지 않으면:

```
보정 없음 (세로로 길쭉)        보정 있음 (제대로 된 원)
      ###                          #########
     #####                       #############
     #####                       #############
      ###                          #########
```

그래서 x만 한 번 더 나눕니다:

```js
const x = (col - (cols - 1) / 2) / (radius * CHAR_ASPECT);
//                                            ↑ 가로만 2로 더 나눔
```

가로로 **2배 많은 칸**을 써야 눈에 정사각형으로 보이기 때문입니다.

#### ④ y축 뒤집기

```js
const y = -(row - (rows - 1) / 2) / radius;
//         ↑ 마이너스
```

터미널은 아래로 갈수록 row가 커지지만 수학은 위로 갈수록 y가 커집니다. 부호 하나로 해결됩니다. **이 마이너스를 빼면 구의 명암이 위아래로 뒤집힙니다.**

### 4-2. 구의 방정식 — "여기 구가 있나?"

원점이 중심이고 반지름이 1인 **단위구(unit sphere)** 의 방정식:

```
x² + y² + z² = 1
```

이 식을 z에 대해 풀면:

```
z² = 1 − x² − y²
z  = ±√(1 − x² − y²)
```

부호가 둘인 이유는 구가 앞뒤로 두 면을 갖기 때문입니다. 우리는 **화면 쪽(앞면)** 만 필요하므로 `+`를 씁니다.

코드에서는 제곱근을 씌우기 **전에** 판정합니다:

```js
const zSquared = 1 - (x * x + y * y);
if (zSquared <= 0) { line += ' '; continue; }   // 구 바깥
const z = Math.sqrt(zSquared);                   // 구 안쪽
```

> **왜 제곱근을 씌우기 전에 판정하나요?** 두 가지 이유가 있습니다.
>
> 1. 음수에 `Math.sqrt`를 쓰면 `NaN`이 나와서 이후 계산이 전부 망가집니다.
> 2. 제곱근은 사칙연산보다 훨씬 느립니다. 배경 픽셀에서는 아예 계산을 건너뛰는 게 이득입니다. 이런 걸 **조기 종료(early exit)** 라고 합니다.

#### 이 판정 하나가 실루엣을 만든다

`zSquared > 0`은 `x² + y² < 1`과 같은 말이고, 이건 **원의 방정식**입니다. 즉 이 한 줄의 조건문이 화면에 완벽한 원을 그립니다. 윤곽선을 그리는 코드가 따로 없다는 점을 주목하세요. **모양은 방정식에서 저절로 나옵니다.**

---

### 4-3. 법선벡터 — 이 코드에서 가장 우아한 부분

**법선(normal)** 은 표면이 "바라보는 방향"입니다. 조명 계산의 필수 재료입니다.

일반적인 곡면에서는 법선을 구하려면 **편미분**을 해야 합니다. 그런데 원점 중심 단위구에서는 마법처럼 간단합니다:

```
표면 위 점의 위치벡터 (x, y, z)  ==  그 지점의 법선벡터
```

#### 왜 그런가?

구의 중심에서 표면의 한 점으로 화살표를 그으면, 그 화살표는 **항상 표면과 수직**입니다. 지구본의 중심에서 표면으로 꼬챙이를 꽂으면 표면에 정확히 90도로 나오는 것과 같습니다.

그리고 더 좋은 소식: `x² + y² + z² = 1` 이므로 이 벡터의 길이는

```
√(x² + y² + z²) = √1 = 1
```

**이미 길이가 1입니다.** 정규화(길이로 나누기)조차 필요 없습니다.

#### 결과

```js
// 법선을 구하는 코드가... 없습니다!
// (x, y, z)를 그냥 쓰면 됩니다.
const dot = x * lightX + y * lightY + z * lightZ;
```

수학이 코드를 지워버린 사례입니다. 구 대신 원기둥이나 도넛을 그리려면 이 특권은 사라지고 진짜로 미분을 해야 합니다.

### 4-4. 내적과 램버트 코사인 법칙 — 이 코드의 심장

#### 내적의 정의 두 가지

**대수적 정의** (계산용):
```
A · B = a₁b₁ + a₂b₂ + a₃b₃
```

**기하적 정의** (의미 이해용):
```
A · B = |A| · |B| · cos θ        (θ는 두 벡터가 이루는 각)
```

두 정의가 같다는 건 코사인 법칙으로 증명됩니다.

#### 두 벡터가 모두 단위벡터라면?

`|A| = |B| = 1` 이므로:

```
A · B = cos θ
```

**내적이 곧 코사인이 됩니다.** 그래서 내적은 이렇게 읽힙니다:

| 내적 값 | 각도 | 의미 |
|---|---|---|
| `1` | 0° | 완전히 같은 방향 → 정면으로 빛을 받음 |
| `0.7` | 45° | 비스듬히 받음 |
| `0` | 90° | 직각 → 빛이 표면을 스쳐 지나감 |
| `-0.7` | 135° | 등지고 있음 |
| `-1` | 180° | 정반대 → 완전한 뒷면 |

**내적 = 두 방향이 얼마나 같은 쪽을 보는지 재는 자.**

#### 램버트의 코사인 법칙

> 표면의 밝기는 법선과 광원 방향이 이루는 각의 **코사인에 비례한다.**

물리적 이유를 그림으로:

```
빛이 수직으로 들어올 때          빛이 45도로 들어올 때

  ↓ ↓ ↓ ↓                          ↘ ↘ ↘ ↘
━━━━━━━━━━━                      ━━━━━━━━━━━━━━━━
  4칸에 4줄기                       6칸에 4줄기
  → 밀도 100%                       → 밀도 약 71% (= cos45°)
```

**같은 양의 빛이 더 넓은 면적에 퍼지므로** 단위면적당 밝기가 줄어듭니다. 이게 지구에서 적도가 덥고 극지방이 추운 이유이기도 합니다.

#### 코드

```js
const dot = x * lightX + y * lightY + z * lightZ;   // 내적
const diffuse = 0.5 * Math.max(0, dot);             // 클램핑 + 세기 조절
```

#### `max(0, ...)`가 꼭 필요한 이유

내적이 음수라는 건 표면이 **광원을 등지고 있다**는 뜻입니다. 그대로 두면 "음의 밝기"가 되어 색이 이상해집니다. 0으로 잘라서 **"빛이 안 닿음"** 으로 처리해야 합니다.

```js
Math.max(0, -0.7)  →  0     // 뒷면은 그냥 어둡게
```

이 한 줄이 없으면 구의 뒷면이 검정을 넘어 색이 반전되는 버그가 납니다.

#### `0.5`는 무엇인가?

전체 밝기 조절 손잡이입니다. 물리적 의미로는 표면의 **반사율(albedo)**, "이 물체가 받은 빛의 몇 %를 되돌려 보내는가"입니다. 값을 키우면 밝은 물체, 줄이면 검은 물체가 됩니다.

---

### 4-5. 삼각함수로 회전 만들기

#### 원의 매개변수 방정식

반지름 `r`인 원 위의 점은 **각도 θ 하나**로 표현됩니다:

```
x = r · cos θ
z = r · sin θ
```

θ를 0부터 2π까지 키우면 점이 원을 한 바퀴 돕니다.

그리고 피타고라스 항등식 `cos²θ + sin²θ = 1` 덕분에:

```
√(x² + z²) = √(r²cos²θ + r²sin²θ) = √(r²) = r
```

**중심과의 거리가 항상 정확히 r로 일정합니다.** 즉 광원이 가까워지거나 멀어지는 일 없이 완벽한 원을 그립니다.

#### 코드

```js
const theta = uTime / 400;
const r = Math.SQRT2;                    // √2 ≈ 1.414
const lightX = Math.cos(theta) * r;
const lightZ = Math.sin(theta) * r;
const lightY = 1;                        // 높이 고정
```

`lightY = 1`로 고정했기 때문에 광원은 **평면 원**이 아니라 **머리 위 비스듬한 원뿔 궤도**를 돕니다. 위에서 비스듬히 비추는 태양 같은 느낌.

#### `/ 400`은 무슨 뜻인가?

`uTime`은 밀리초입니다. 그냥 쓰면 1초에 수백 바퀴를 돌아 아무것도 안 보입니다.

```
한 바퀴 = 2π ≈ 6.283 라디안
θ = t / 400  이므로  t = 6.283 × 400 ≈ 2513 밀리초 ≈ 2.5초
```

- **숫자를 키우면** (예: 800) → 느려짐 (5초에 한 바퀴)
- **숫자를 줄이면** (예: 200) → 빨라짐 (1.25초에 한 바퀴)

#### 왜 하필 √2인가?

계산이 예뻐지기 때문입니다. 광원 벡터의 길이를 구해보면:

```
|light| = √( (√2·cosθ)² + 1² + (√2·sinθ)² )
        = √( 2cos²θ + 1 + 2sin²θ )
        = √( 2(cos²θ + sin²θ) + 1 )
        = √( 2·1 + 1 )
        = √3
```

**θ가 어떻게 변하든 길이가 항상 √3으로 일정합니다.**

엄밀히 하려면 내적 전에 광원을 정규화(길이로 나누기)해야 진짜 `cos θ`가 나옵니다. 그런데 길이가 상수 √3이므로, 정규화를 생략하면 모든 픽셀의 밝기가 √3배로 **똑같이** 커질 뿐 명암의 **모양은 완전히 동일**합니다. 그래서 원본 코드도 정규화를 생략했습니다. (그만큼 `0.5` 손잡이로 보정)

### 4-6. 색은 벡터, 조명은 벡터 연산

```js
const cr = SKY[0] * diffuse + GROUND[0];
const cg = SKY[1] * diffuse + GROUND[1];
const cb = SKY[2] * diffuse + GROUND[2];
```

수식으로 쓰면:

```
최종색 = SKY × diffuse + GROUND
         └── 스칼라 곱 ──┘   └ 벡터 합 ┘
```

#### 스칼라 곱 부분: `SKY × diffuse`

```
(0.5, 0.85, 1.5) × 0.4 = (0.20, 0.34, 0.60)
```

세 성분의 **비율**(0.5 : 0.85 : 1.5)이 유지됩니다. → 밝은 쪽이든 어두운 쪽이든 **같은 푸른빛**을 유지합니다. 현실에서도 그림자는 "빛이 줄어든 것"이지 "다른 색"이 아니죠.

#### 벡터 합 부분: `+ GROUND`

`GROUND`는 `diffuse`와 무관한 **상수**입니다. 빛이 전혀 닿지 않아 `diffuse = 0`인 뒷면에서도:

```
(0, 0, 0) + (0.2, 0.1, 0.05) = (0.2, 0.1, 0.05)
```

가 남습니다. **덕분에 그림자가 완전한 검정으로 뭉개지지 않습니다.**

`GROUND`는 빨강(0.2)이 가장 세므로 그림자에 **따뜻한 붉은 기**가 돌고, `SKY`는 파랑(1.5)이 가장 세므로 밝은 쪽은 **차가운 푸른 기**가 돕니다. 이 **따뜻함/차가움의 대비**가 그림을 살아 있게 만드는 미술의 기본 원리입니다.

#### 1.5는 왜 1을 넘나?

색 값이 1을 넘는 것을 **HDR(High Dynamic Range)** 이라고 합니다. 최종 단계에서 `clamp01`로 어차피 0~1로 자르므로, 1.5는 **"이 성분은 쉽게 포화(saturate)된다"** 는 뜻이 됩니다. 파랑이 먼저 최대치에 도달하면서 밝은 부분이 하얗게 날아가는 느낌을 만듭니다.

### 4-7. 휘도 — 색 3개를 밝기 1개로

우리에겐 R, G, B 세 개가 있는데 골라야 할 문자는 **하나**입니다.

#### 왜 단순 평균 `(R+G+B)/3`은 틀린가?

사람 눈은 색마다 밝기를 다르게 느낍니다. 순수한 초록 `(0,1,0)`과 순수한 파랑 `(0,0,1)`을 나란히 놓으면 **초록이 훨씬 밝게** 보입니다. 눈의 원추세포가 초록 파장(약 555nm)에 가장 민감하고 파랑에는 둔감하기 때문입니다.

#### 국제 표준 가중치 (Rec.709)

```
Y = 0.2126·R + 0.7152·G + 0.0722·B
─            ──────       ──────       ──────
휘도          빨강 21%     초록 72%     파랑 7%
```

`Y`는 휘도의 관례적 기호입니다.

**가중치 세 개를 더하면 정확히 1이 됩니다:**
```
0.2126 + 0.7152 + 0.0722 = 1.0000
```

이건 우연이 아니라 **필수 조건**입니다. 합이 1이어야 흰색 `(1,1,1)`에서 `Y=1`(최대), 검정 `(0,0,0)`에서 `Y=0`이 나와 범위가 정확히 맞습니다.

#### 계산 예시

밝은 지점의 색 `R=0.45, G=0.53, B=0.80`:

```
Y = 0.2126 × 0.45  +  0.7152 × 0.53  +  0.0722 × 0.80
  = 0.0957         +  0.3791         +  0.0578
  = 0.5326
```

주목할 점: **파랑(0.80)이 숫자상 가장 큰데 기여는 0.0578로 가장 작습니다.** 초록은 0.53밖에 안 되는데 기여는 0.3791로 압도적입니다.

(참고로 단순 평균이었다면 `(0.45+0.53+0.80)/3 = 0.593`으로 더 밝게 나옵니다. 파랑을 과대평가한 결과입니다.)

### 4-8. 램프 인덱싱 — 실수를 문자로

#### 인덱싱이란?

**인덱스(index)** 는 배열·문자열의 칸 번호이고, **인덱싱**은 그 번호로 값을 꺼내는 것입니다. 대괄호를 씁니다.

```js
const RAMP = " .:-~=+*#%@";
//  인덱스:   0123456789↑
//                      10

RAMP[0]   // ' '  공백, 가장 어두움
RAMP[1]   // '.'
RAMP[5]   // '='
RAMP[10]  // '@'  가장 밝음
RAMP[11]  // undefined  ← 범위 밖!
```

번호가 **1이 아니라 0부터** 시작하는 것을 **0 기반 색인(0-based index)** 이라고 합니다. JavaScript, C, Java, Python 등 대부분의 언어가 이 방식입니다. 그래서 문자가 11개면 유효 번호는 **0 ~ 10**입니다.

#### 왜 이 문자 순서인가?

문자가 차지하는 **"잉크의 양"이 곧 밝기**이기 때문입니다.

```
' '  아무것도 안 칠함              → 가장 어두움
'.'  점 하나                       → 조금 밝음
':'  점 둘
'-'  가로선
'~'  물결
'='  가로선 둘
'+'  십자
'*'  별
'#'  격자
'%'  꽉 참
'@'  거의 완전히 참                → 가장 밝음
```

**문자를 픽셀의 밝기 단계로 재활용**하는 것입니다. ASCII 아트의 근본 아이디어입니다.

#### 양자화 공식

`Y`는 `0.5326` 같은 **연속된 실수**이고, 번호는 **0~10의 정수**입니다. 연속값을 띄엄띄엄한 단계로 바꾸는 것을 **양자화(quantization)** 라고 합니다. 아날로그 소리를 MP3로, 아날로그 사진을 JPEG으로 바꿀 때 하는 일과 같습니다.

```
index = round( Y × (문자 개수 − 1) )
```

**▸ 왜 `(문자 개수 − 1)`을 곱하나?**

문자가 11개일 때 그냥 11을 곱하면:
```
Y = 1.0  →  1.0 × 11 = 11  →  RAMP[11] = undefined  ❌
```

마지막 유효 번호는 10이므로 **10을 곱해야** 합니다:
```
Y = 1.0  →  1.0 × 10 = 10  →  RAMP[10] = '@'  ✅
Y = 0.0  →  0.0 × 10 =  0  →  RAMP[0]  = ' '  ✅
```

일반화: **"0부터 N−1까지 N칸에 0~1을 펼치려면 (N−1)을 곱한다."**

**▸ 왜 `round`(반올림)인가?**

내림(`floor`)을 쓰면 `Y=0.99`에서 `9.9 → 9`가 되어, 가장 밝은 `'@'`는 `Y`가 **정확히 1.0**일 때만 나옵니다. 거의 안 나오죠.

반올림하면 각 문자가 **똑같은 폭(1/10 = 0.1)의 구간**을 공평하게 담당합니다. (단, 양 끝 `' '`와 `'@'`는 절반 폭인 0.05씩만 담당합니다.)

#### 최종 계산 예시

```
Y = 0.5326
0.5326 × 10 = 5.326
round(5.326) = 5
RAMP[5] = '='
```

#### 구간표 (문자 11개 기준)

| 인덱스 | Y 범위 | 문자 |
|:---:|:---:|:---:|
| 0 | 0.00 ~ 0.05 | (공백) |
| 1 | 0.05 ~ 0.15 | `.` |
| 2 | 0.15 ~ 0.25 | `:` |
| 3 | 0.25 ~ 0.35 | `-` |
| 4 | 0.35 ~ 0.45 | `~` |
| 5 | 0.45 ~ 0.55 | `=` |
| 6 | 0.55 ~ 0.65 | `+` |
| 7 | 0.65 ~ 0.75 | `*` |
| 8 | 0.75 ~ 0.85 | `#` |
| 9 | 0.85 ~ 0.95 | `%` |
| 10 | 0.95 ~ 1.00 | `@` |

#### 계조를 바꿔보기

- 문자를 **늘리면** (예: 32개) → 부드러운 그라데이션
- 문자를 **줄이면** (예: 4개 `" .*@"`) → 판화·포스터 같은 거친 느낌

이건 화면의 **해상도**를 바꾸는 게 아니라 **계조(階調)** 를 바꾸는 것입니다.

## 5. 코드와 수학 대응표

코드 한 줄이 어떤 수학에 대응하는지 정리했습니다. 왼쪽이 코드, 오른쪽이 수학입니다.

**좌표계 변환** — 평행이동 + 스케일
`(col - (cols-1)/2) / (radius * CHAR_ASPECT)`

**좌표계 방향 맞추기** — y축 반전
`-(row - (rows-1)/2) / radius`

**구의 방정식** — `z² = 1 − x² − y²`
`1 - (x*x + y*y)`

**원의 내부 판정 (실루엣)** — `x² + y² ≥ 1`
`zSquared <= 0`

**구 표면의 깊이** — `z = √(1−x²−y²)`
`Math.sqrt(zSquared)`

**단위구의 특수 성질** — 위치 = 법선
`(x, y, z)`를 그대로 사용

**내적** — `N · L`
`x*lx + y*ly + z*lz`

**램버트 법칙 + 뒷면 차단** — `max(0, cos θ)`
`Math.max(0, dot)`

**원의 매개변수 방정식** — `(r cos θ, r sin θ)`
`Math.cos(t)*Math.SQRT2`, `Math.sin(t)*Math.SQRT2`

**밝기 조절** — 스칼라 곱
`SKY[i] * diffuse`

**환경광 더하기** — 벡터 합
`... + GROUND[i]`

**휘도 (Rec.709)** — 가중 평균 `Y`
`0.2126*r + 0.7152*g + 0.0722*b`

**양자화** — 연속 → 이산
`Math.round(Y * (N-1))`

**인덱싱** — 밝기 → 문자
`RAMP[index]`

## 6. 직접 해보는 실습

`sphere.js`의 값을 하나씩 바꾸고 `node sphere.js`로 다시 실행해 보세요. **한 번에 하나씩만 바꾸는 것**이 중요합니다. 무엇이 무엇을 바꿨는지 알려면요.

### 난이도 ★ — 상수 바꾸기

**회전 속도** — `uTime / 400` 을 `uTime / 150` 으로
2.6배 빨라집니다.

**계조 줄이기** — `RAMP = " .*@"`
판화 같은 거친 명암이 됩니다.

**계조 늘리기** — 아래 코드블록의 70단계 램프로 교체
아주 부드러운 그라데이션이 됩니다.

**빛 색 바꾸기** — `SKY = [1.5, 0.6, 0.3]`
노을빛 구가 됩니다.

**환경광 끄기** — `GROUND = [0, 0, 0]`
그림자가 완전한 검정이 됩니다.

**반사율 올리기** — `0.5 * Math.max(...)` 를 `1.2 * ...` 로
훨씬 밝은, 하얗게 뜬 구가 됩니다.

**광원 높이** — `lightY = 1` 을 `lightY = 0` 으로
빛이 위가 아니라 옆에서만 들어옵니다.

70단계 램프(널리 쓰이는 표준 문자열)를 그대로 붙여넣을 때:

```js
const RAMP = " .'`^\",:;Il!i><~+_-?][}{1)(|\\/tfjrxnuvczXYUJCLQ0OZmwqpdbkhao*#MW&8%B@$";
```


### 난이도 ★★ — 수학 건드리기

**① y축 반전 없애기** — `-(row - ...)`에서 마이너스를 지워보세요. 명암이 위아래로 뒤집힙니다. 이걸로 "부호 하나가 좌표계를 바꾼다"를 확인.

**② 클램핑 없애기** — `Math.max(0, dot)` → `dot` 뒷면의 음수 밝기가 어떻게 그림을 망가뜨리는지 확인하세요.

**③ 종횡비 없애기** — `CHAR_ASPECT = 1` 구가 세로로 길쭉해집니다.

**④ 정사영을 원근 투영으로** `z`를 이용해 멀리 있는 부분을 어둡게 (거리 감쇠):
```js
const fog = z;                          // z가 클수록 앞쪽(가까움)
line += brightnessToChar(cr*fog, cg*fog, cb*fog);
```

**⑤ 광원 두 개 만들기**
```js
// 반대편에서 오는 보조광 추가
const dot2 = x * (-lightX) + y * 0.3 + z * (-lightZ);
const diffuse2 = 0.2 * Math.max(0, dot2);
const cr = SKY[0]*diffuse + FILL[0]*diffuse2 + GROUND[0];
```

### 난이도 ★★★ — 새 기능

**⑥ 하이라이트(specular) 추가 — 반짝이는 금속 구**

Phong 모델: 시선 방향 `V=(0,0,1)`, 반사 벡터 `R = 2(N·L)N − L`

```js
const nl = Math.max(0, dot / Math.sqrt(3));   // 정규화된 N·L
const rz = 2 * nl * z - lightZ / Math.sqrt(3);
const spec = Math.pow(Math.max(0, rz), 32) * 0.8;   // 32 = 광택 지수
// 색에 spec을 그냥 더하면 됩니다 (하이라이트는 보통 흰색)
```

**⑦ 진짜로 구를 회전시키기 (회전행렬 + 텍스처)**

y축 회전행렬:
```
| cos θ   0   sin θ |
|   0     1     0   |
| −sin θ  0   cos θ |
```

```js
// 표면 점 (x,y,z)를 반대로 회전시켜 '구의 고유 좌표'를 얻는다
const wx =  Math.cos(-theta)*x + Math.sin(-theta)*z;
const wz = -Math.sin(-theta)*x + Math.cos(-theta)*z;
// 경도/위도로 변환 → 체크무늬
const lon = Math.atan2(wz, wx);
const lat = Math.asin(y);
const checker = (Math.floor(lon*4/Math.PI) + Math.floor(lat*4/Math.PI)) % 2;
```

이제 **광원을 고정하고 구를 돌려도** 무늬 덕분에 회전이 보입니다.

## 7. 확장 아이디어 (수업 프로젝트용)

### A. 도넛 만들기 — `donut.c` 오마주

전설적인 [donut.c](https://www.a1k0n.net/2011/07/20/donut-math.html)처럼 토러스(도넛)를 그려보세요. 난이도가 확 올라갑니다:

- 구와 달리 **위치 ≠ 법선**입니다. 진짜로 법선을 계산해야 합니다.
- 화면 좌표에서 표면을 역산하기 어려우므로, 반대로 **표면 위의 점들을 화면에 뿌리는** 방식(포인트 렌더링)을 씁니다.
- 그러면 **Z-버퍼**가 필요합니다. 같은 칸에 여러 점이 겹칠 때 "더 앞에 있는 것만 그리기"를 하는 배열입니다.

배우는 것: 매개변수 곡면, 법선 계산, 깊이 버퍼, 회전행렬

### B. 레이 마칭 + SDF — 임의의 도형 그리기

**SDF(Signed Distance Function, 부호 있는 거리 함수)**: 공간의 한 점을 넣으면 "가장 가까운 표면까지의 거리"를 돌려주는 함수입니다.

```js
const sdfSphere = (px,py,pz,r) => Math.hypot(px,py,pz) - r;
const sdfBox = (px,py,pz,b) => { /* ... */ };
// 두 도형 합치기: Math.min(a, b)
// 두 도형 빼기:   Math.max(a, -b)
// 부드럽게 섞기:  smooth minimum
```

카메라에서 광선을 쏘고, SDF가 알려주는 거리만큼씩 전진하다가 거리가 0에 가까워지면 "표면에 닿았다"고 판정합니다.

배우는 것: 함수형 기하, 반복 알고리즘, 불리언 연산

### C. 컬러 터미널 — ANSI 24비트 색

문자만 쓰지 말고 진짜 색을 입혀보세요:

```js
const ansi = (r,g,b,ch) =>
  `\x1b[38;2;${Math.round(r*255)};${Math.round(g*255)};${Math.round(b*255)}m${ch}`;
```

그러면 `SKY`의 푸른빛과 `GROUND`의 붉은빛이 실제로 보입니다. 휘도로 문자를 고르고, 색으로 칠하면 둘 다 살릴 수 있습니다.

배우는 것: ANSI 이스케이프, 색 공간, 성능(문자열 길이가 10배가 됨)

### D. 브라우저로 옮기기

`frame()` 함수는 순수 함수라 그대로 웹에서 돌아갑니다:

```html
<pre id="screen" style="font: 12px/1 monospace"></pre>
<script type="module">
  // sphere.js에서 frame 함수만 복사해 오거나 ES module로 import
  const screen = document.getElementById('screen');
  const start = performance.now();
  function loop(now) {
    screen.textContent = frame(now - start, 80, 40);
    requestAnimationFrame(loop);
  }
  requestAnimationFrame(loop);
</script>
```

배우는 것: `requestAnimationFrame`, DOM, 순수 함수의 이식성

### E. 성능 측정 — 알고리즘 복잡도 체감하기

```js
console.time('frame');
frame(0, 200, 60);
console.timeEnd('frame');
```

화면을 2배로 키우면 시간이 **4배**가 됩니다. 칸 수가 `cols × rows`이므로 **O(n²)** 이기 때문입니다.

- 배경 픽셀에서 `continue`로 조기 종료하면 얼마나 빨라지나?
- `Math.sqrt`를 몇 번이나 호출하나? 줄일 수 있나?
- 문자열 `+=` 대신 배열에 담아 `join`하면 빨라지나?

배우는 것: 시간복잡도, 프로파일링, 최적화의 실제 효과

### F. 다른 물체 스스로 유도해보기

**원기둥** ★★
`x² + y² = 1` (z 범위 제한)

**타원체** ★★
`(x/a)² + (y/b)² + (z/c)² = 1`

**원뿔** ★★★
`x² + y² = (kz)²`

**토러스** ★★★★
`(√(x²+y²) − R)² + z² = r²`

각각 법선을 어떻게 구할지가 진짜 과제입니다. (힌트: 음함수 `F(x,y,z)=0`의 법선은 그래디언트 `∇F`입니다.)

## 8. 자주 묻는 질문

**Q. 이 코드는 무슨 언어인가요? C인가요?** JavaScript입니다. `const`, 화살표 함수 `(x) => {}`, `Math.sqrt`가 그 증거입니다. 원본 데모는 three.js의 `Vector3` 클래스를 썼지만, 이 저장소 버전은 의존성 없이 숫자만으로 다시 썼습니다.

**Q. 원본의 `echo`, `shader`, `uTime`, `b2ASCII`는 표준 함수인가요?** 아닙니다. 그 데모가 만든 **자체 헬퍼**입니다. GLSL 프래그먼트 셰이더를 JavaScript로 흉내 낸 구조입니다. `shader(픽셀 => 색)`을 화면 전체에 돌리고 `b2ASCII`로 색을 문자로 바꿉니다.

**Q. 왜 구가 아니라 빛을 돌리나요?** 단색 구는 어느 방향으로 돌려도 모양이 같아서, 빛만 돌려도 눈에는 구가 도는 것처럼 보입니다. 계산이 훨씬 쌉니다. 텍스처(무늬)를 입히는 순간 이 트릭은 통하지 않고, 진짜 회전행렬이 필요해집니다.

👉 [7-⑦ 실습](#난이도---새-기능)

**Q. 왜 광원 벡터를 정규화하지 않나요?** `√2`를 반지름으로 쓴 덕분에 광원 벡터 길이가 항상 `√3`으로 **일정**합니다. 상수배는 명암의 모양을 바꾸지 않고 전체 밝기만 바꾸므로, `0.5`라는 세기 조절값으로 흡수할 수 있어서 생략했습니다.

**Q. `zSquared`를 왜 따로 변수로 뒀나요?** ① 음수에 `Math.sqrt`를 쓰면 `NaN`이 되어 이후 계산이 망가지고, ② 제곱근은 느린 연산이라 배경 픽셀에서는 아예 건너뛰는 게 이득이기 때문입니다.

**Q. 터미널 없이 웹에서 보고 싶어요.** `frame()`은 순수 함수라 그대로 브라우저에서 돌아갑니다.

👉 [7-D 브라우저로 옮기기](#d-브라우저로-옮기기)

**Q. 계조(문자 개수)를 늘리면 화질이 좋아지나요?** '해상도'가 아니라 '명암 단계'가 촘촘해집니다. 그라데이션이 부드러워지지만, 문자마다 실제 밝기가 균일하지 않아서 (폰트에 따라 `%`가 `#`보다 어두울 수도 있음) 어느 지점부터는 오히려 얼룩덜룩해질 수 있습니다. 직접 실험해 보는 게 가장 좋습니다.
